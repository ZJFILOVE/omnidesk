# 视频字幕与 Linux 播放器接入方案

状态：最初的调研与设计，保留用于说明取舍。2026-09-14 已实现完整预处理、字幕网站接入、自动对齐与外部播放器适配；当前能力、验证范围及限制以 [视频字幕使用说明](VIDEO_SUBTITLES.zh-CN.md) 为准。增量播放和 libmpv 内嵌仍为后续方案。

## 目标与选型结论

新增独立的“视频字幕”页面，接受 YouTube 链接和本地视频。优先读取已有字幕，无可用字幕时提前识别音轨，再翻译并交给播放器显示。

选型面向 Linux 可用方案，不以当前机器安装了什么为约束。建议统一生成标准字幕，第一阶段支持完整预处理后在用户选择的播放器观看；需要边处理边播放时，优先实现 mpv 外部进程适配器。未来若需要在 Qt 窗口内观看，再接入 libmpv。

## Linux 方案比较

下表中的集成取舍是针对本项目的工程判断，不是播放器性能排名。

| 方案 | 官方资料确认的能力 | 本项目适用方式与待验证项 |
| --- | --- | --- |
| mpv / libmpv | 外部 JSON IPC、字幕加载和重载、可嵌入的播放后端 | 优先做自动同步及增量字幕；先外部窗口，内嵌另做渲染验证 |
| Haruna | libmpv 后端、yt-dlp 在线播放、自定义 mpv 命令 | 现成 GUI 候选；不能因使用 libmpv 就假设它对外提供完整 IPC，自动接入需验证 |
| SMPlayer | 可选 mpv 后端、双字幕及视频网站播放 | 现成 GUI 候选；验证启动时传入字幕、复用实例及播放进度控制 |
| Celluloid | GTK 的 mpv 前端 | 现成 GUI 候选；外挂字幕和远程控制参数需按版本验证 |
| VLC / libVLC | 可嵌入播放库，支持向当前媒体添加外部字幕 | 适合完整字幕及另一种内嵌后端；YouTube 解析仍由应用的 yt-dlp 层负责 |
| Qt Multimedia | QMediaPlayer 提供位置、倍速、字幕轨选择和视频输出 | 与现有 Qt 界面贴合，但不能将内置字幕轨选择当成任意外挂字幕热更新接口，需要额外实现或验证 |
| GStreamer | playbin 支持网络缓冲、外部字幕 suburi、轨道选择 | 适合定制媒体管道；本项目目前不需要为此增加管道和渲染集成工作 |

官方来源：[mpv](https://mpv.io/manual/stable/)、[Haruna](https://haruna.kde.org/)、[SMPlayer](https://www.smplayer.info/en/mpv)、[Celluloid](https://github.com/celluloid-player/celluloid)、[libVLC](https://videolan.videolan.me/vlc-3.0/group__libvlc__media__player.html)、[Qt Multimedia](https://doc.qt.io/qt-6/qmediaplayer.html)、[GStreamer](https://gstreamer.freedesktop.org/documentation/playback/playbin.html)。

## 用户流程

页面提供“粘贴 YouTube 链接”和“选择本地视频”，然后显示标题、时长、音轨及发现的字幕。主要操作为“准备字幕”“播放”“导出字幕”，任务支持取消和继续。

准备方式分为：

- 完整准备：识别、翻译全部完成后播放。适用于所有经验证能加载导出格式的播放器，重看无需再处理。
- 提前准备一段：先完成开头字幕再播放，后台继续处理。仅对支持进度反馈与字幕更新的播放器适配器开放。

显示实际阶段与已处理的媒体时长，例如“正在识别 · 12:30 / 48:00”和“已准备至 05:20”；有测量数据后才估计剩余时间。

### 本地视频

1. 探测音轨、内嵌字幕和同名外挂字幕；允许用户选择音轨或另选字幕文件。
2. 质量合适的目标语言字幕直接使用；源语言文本字幕进入翻译。
3. 无可用文本字幕时，FFmpeg 解码所选音轨，ASR 生成带时间戳的字幕。图片字幕不能当作文本直接翻译；初版可走 ASR。
4. 生成原文、译文和双语字幕，播放原视频。无需重新压制画面，也无需烧录字幕。

### YouTube 链接

1. yt-dlp 获取元数据及可用字幕，优先采用选定语言的人工字幕，再考虑源语言自动字幕。
2. 抓取失败与“没有字幕”分开报告；请求错误不能直接视为无字幕。
3. 有字幕时只获取字幕，视频可以在线播放，也可以选择下载后播放。
4. 无字幕时下载音轨用于 ASR。若选离线观看，同时准备视频文件，不能将仅有音轨的缓存显示成可离线观看的视频。
5. 在线播放使用同一内容版本及时间轴；链接失效时重新解析。初版不做片段裁剪或跳广告，以免字幕时间轴与视频不一致。

yt-dlp 的字幕、音频格式选择及下载能力见[官方文档](https://github.com/yt-dlp/yt-dlp)。

## 融入当前项目

建议分出以下职责，名称为拟议文件名：

| 模块 | 职责 |
| --- | --- |
| `video_sources.py` | 本地探测、YouTube 元数据、字幕与媒体下载 |
| `video_subtitles.py` | 文本字幕解析、时间轴、带时间戳 ASR、字幕导出 |
| `video_jobs.py` | 阶段进度、取消、续做、翻译调度 |
| `video_cache.py` | 媒体身份、字幕与译文缓存、原子写入 |
| `video_player.py` | 播放器能力接口及 mpv 适配器 |
| `video_ui.py` | 视频输入、准备进度、播放与导出操作 |

复用 `text_translation.py` 的翻译提供方与凭据配置；视频批量请求单独实现有编号的输入输出协议，检查漏句、重复编号和错误返回。不能直接把多条字幕拼成一段后猜测如何拆回去。

`native_worker.py` 新增视频任务入口，继续使用 JSONL 输出进度。视频任务不依赖 PipeWire 设备准备，不应调用实时会话的设备检查或音频路由初始化。

`native_app.py` / `desktop_ui.py` 新增页面；当前导航名称和索引在多处硬编码，增加页面时集中管理，避免影响历史页、偏好设置和错误恢复跳转。

字幕统一保存 `id、start_ms、end_ms、source_text、translated_text、status`。文件 ASR 输出的局部时间须加分块偏移，不能删除静音后直接拼接时间。分块在停顿处分割，必要时重叠并去重，保留无语音区间。

本机现有 FunASR 二进制帮助列出了 `--srt`，可作为接入起点；目前 `local_subtitles.recognize()` 只返回纯文本。尚需验证 SRT 的输出通道、断句粒度、长静音、分块边界与时间戳精度，不能凭存在该选项就宣称同步问题已解决。

视频任务使用可续做的完整任务队列，不能复用实时管道中队列满时丢弃旧片段的策略。

## 播放与延迟

完整字幕模式下，播放器依字幕时间轴显示。暂停、跳转和倍速由播放器自行处理，不再以“模型返回时刻”更新悬浮字幕。

mpv 增量模式拟使用 JSON IPC 观察播放位置、暂停、倍速及文件切换；通过 `sub-add` 加载字幕，写入新版后用 `sub-reload` 刷新。字幕重载时的闪烁、选中轨道及异步命令完成时机都要实测。

调度以“当前播放位置起，连续有可用字幕的区间”为依据，不能把远处完成的一段当作中间也已准备好。跳转后优先处理新位置；旧请求的结果可缓存，但不得覆盖新视频的任务状态。

初始可尝试准备前 20～30 秒后播放，维持约 60～120 秒的媒体领先量；这些是实验参数。最终应按实测处理吞吐、翻译尾延迟和播放倍速调整。首批用小请求减少开播等待，后台再采用较大批次。

缓冲不足时，由模式决定暂时显示原文还是暂停等待。不能许诺任意倍速或任意跳转都无需等待。判断是否跟得上应测下载、解码、ASR、翻译的整条链路。

外部播放器启动时传入完整字幕是通用接入；边处理边看需要专用适配器。默认程序打开文件并不等于能控制字幕更新，不能对所有播放器承诺相同体验。

若以后内嵌 Qt，优先评估 libmpv render API。mpv 的 `--wid` 文档描述了 X11 等平台的窗口句柄方式，不应将它作为原生 Wayland 通用嵌入方案。需要验证 Qt 渲染上下文、硬件解码、缩放与全屏。[mpv 嵌入说明](https://mpv.io/manual/stable/#embedding-into-other-programs-libmpv)

## 缓存与兼容输出

视频字幕缓存与实时会话历史分开管理。界面明确显示缓存位置、空间及清除操作，并更新当前“本机不保存字幕”的说明，使其准确区分两种模式。

- YouTube 缓存键包含视频 ID、音轨或字幕轨身份；本地视频包含文件身份及变化检测。
- 转录键包含源语言、模型版本、所选音轨及分段参数。
- 翻译键包含字幕内容、目标语言、提供方、模型及提示词版本；不包含密钥。
- 原文与译文独立保存，中断后只补未完成部分。下载与输出使用临时文件，成功后原子替换。
- 提供原文 SRT、译文 SRT、双语 SRT；ASS 可用于增强样式，渲染结果按播放器验证。

## 实施顺序与验收

1. 本地视频完整预处理：探测已有字幕、无字幕 ASR、翻译、导出，验证在 mpv 和至少另一种现成 Linux 播放器中加载。
2. YouTube：字幕优先，无字幕下载音轨后接入同一管道；分别验证在线与离线播放，处理网络错误及取消。
3. mpv 自动接入：从应用启动受管理的播放器实例，加载字幕并监听时间；不假设可以接管任意已打开的实例。
4. 增量准备：首批开播、字幕刷新、拖动进度后重新调度、倍速和缓冲不足行为。
5. 根据实际体验选择是否嵌入 libmpv，或扩展 Haruna、SMPlayer、VLC 适配器。

关键验收样本：有外挂字幕、有内嵌字幕、多音轨、无字幕、长静音、快速连续讲话、长视频，以及有人工字幕/自动字幕/无字幕的 YouTube 录播。验证暂停、前后跳转、倍速、重看缓存、取消后续做、翻译失败重试、中文及特殊字符路径、播放器退出。

当前完成的是官方资料调研和本项目代码接入点检查；未安装额外播放器，未运行 YouTube 下载、整片 ASR 或播放器自动接入测试。
