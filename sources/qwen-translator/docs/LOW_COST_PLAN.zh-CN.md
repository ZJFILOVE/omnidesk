# 只有字幕：本地 GPU 识别 + 文本翻译

已实现于原生 Qt 应用。保留原来的 Qwen 语音同传模式，新增 **只有字幕 · 本地 FunASR**。

```text
正在播放声音的输出设备 / 麦克风
  → PipeWire 16 kHz 单声道 PCM
  → 分句 + FSMN-VAD
  → FunASR SenseVoiceSmall Q8（llama.cpp / Vulkan GPU）
  → 原文立即显示
  → Codex Luna / 兼容 API（仅文字）
  → 译文与悬浮字幕
```

## 使用

1. 实时翻译页选择 **实时字幕 · 仅看双语字幕（静音）**。
2. 收音来源选择浏览器或播放器正在使用的输出设备（例如 **系统声音 · 当前耳机或扬声器**），也可选麦克风。默认跟随启动/刷新时的系统默认输出，不自动跟随会话中的设备切换。
3. 选择“听英文 → 看中文字幕”或“说中文 → 看英文字幕”。
   在 **字幕响应** 中选择 **快速字幕**（默认，优先跟上声音）或 **完整优先**（较少翻译请求）；开始前可切换，选择会保存。
4. 偏好设置 → 字幕文本翻译：默认 **本机 Codex**，首次选择 **gpt-5.6-luna**。模型通过下拉菜单选择，启动时自动读取本机 Codex 列表，也可点击 **刷新模型列表**；选择会自动保存。可先点击测试翻译连接。
5. 点击开始翻译；需要字幕窗口时点击悬浮字幕。结束时点击结束翻译。

字幕模式无需百炼语音 API Key。它不创建音频播放进程，也不移动浏览器输出；原声保持原有播放方式。若浏览器先前被移到了 `meeting-remote`，请将浏览器恢复为实际输出设备，再选择对应的系统声音作为字幕来源。

也可以直接打开到字幕模式（不会自动开始采集）：

```bash
.venv/bin/python launch_app.py --subtitles
```

## 本地识别

采用 FunASR 家族的多语言 **SenseVoiceSmall Q8**，不是 Fun-ASR-Nano。使用官方 **llama.cpp/GGUF runtime v0.2.6**，无需安装 PyTorch。识别权重约 254 MB，FSMN-VAD 约 1.7 MB；均校验 SHA-256。默认 **Vulkan GPU**，本机验证使用 NVIDIA GeForce RTX 4070 Laptop GPU。CPU 只作为设备页面的手动备用项，不会自动降级。

文件位于 `runtime/funasr/` 与 `models/funasr/`，已加入 Git 忽略列表。重新安装：

```bash
python3 scripts/setup_local_asr.py
```

安装脚本下载固定版本运行时与校验过的权重；需能访问 GitHub 和 Hugging Face。GPU 推理需要可用的 Vulkan 驱动。

## 翻译模型

**本机 Codex**：字幕会话调用 `codex app-server`，复用 CLI 登录，不读取或复制认证文件。每段使用独立 `ephemeral` 临时会话；单次 CLI 适配器仍保留用于对照。默认 Luna，也可从菜单选择其他模型。菜单通过 [Codex App Server 的 model/list 接口](https://learn.chatgpt.com/docs/app-server#list-models-modellist)读取本机 CLI 的可见文字模型，支持分页；查询列表不发起模型对话。刷新失败时保留原选择，已保存模型不在新列表中时明确标注，实际可用性可通过测试翻译连接确认。使用临时工作目录，通过 stdin 传入文字并读取 JSONL 输出；禁用 shell、浏览器、插件、应用连接和多代理工具。本机在 2026-09-14 验证时为 ChatGPT 登录，Luna 调用成功。额度归属取决于实际 CLI 登录方式，不把订阅额度视为通用 API Key。

每个分段是独立的临时请求，当前字幕会话复用一个 Codex App Server 进程，并为每段新建临时上下文；结束会话即清理服务进程。模型处理与网络耗时仍存在，不能保证实时逐词翻译。早期 CLI 示例中单次 Luna 翻译约 8.4 秒，GPU ASR 约 0.28–0.40 秒；当前服务小样本为 4.17–5.09 秒，测试句与时间不同，不作严格速度比较。字幕先显示原文，然后补译文。

**兼容 API**：填写 API 基础地址、模型名，选择 Chat Completions 或 Responses。地址可为本机或远程服务，例如 `http://127.0.0.1:1234/v1`。本机免鉴权服务允许 Key 为空；其他 Key 通过按钮按地址存入系统密钥库。更改地址会清空界面中的旧 Key，防止误送到其他服务。回环地址直连；远程地址遵循系统代理配置。不跟随 HTTP 重定向。

**仅原文**：本地识别后直接显示，不调用文本翻译服务。

思考等级可随模型选择，默认优先 low，并分别记住每个模型的选择。现在使用专用翻译指令减少 Codex 固定输入，并在会话内复用完全相同字幕的译文；界面可预览提示词、查看实际 token 用量。固定句实测输入约减少 58%，详见[提示词、用量与上下文取舍](TRANSLATION_TOKENS.zh-CN.md)。

## 分段、积压与隐私

- **快速字幕**：约 0.4 秒静音后分句，最长 4 秒一段；识别和翻译各保留最多 1 段待处理内容。悬浮原文立即更新，上句译文保留并标注“上句译文 · 新句翻译中”，当前句译文到达后移除标注。短分段可能切开句子，并增加翻译请求及固定输入开销。
- **完整优先**：约 0.65 秒静音后分句，最长 8 秒一段；ASR 待处理队列最多 2 段，翻译队列最多 3 段。悬浮字幕按原文、译文成对更新，更连贯但等待更久；最长 8 秒仍可能切开长句，并不保证完整转写。
- 两种模式处理跟不上时都会丢弃最旧的待处理片段并显示提示，避免字幕无限落后。因此它适合实时字幕，不作为完整录音转写档案。设备页面可调声音触发阈值；FSMN-VAD 进一步过滤候选片段。
- 主窗口原文与译文使用句子编号配对；迟到的旧译文仍加入对应正文，但不会替换更新的悬浮译文。
- 主窗口分别显示音频片段时长、识别排队、ASR 实际调用耗时、翻译排队和翻译耗时。“分段结束 → 译文”不含前面的音频收集时间；4 秒分段不是保证 4 秒内出译文。
- 翻译服务失败时保留原文并提示；采集设备断开或 ASR 失败时停止会话。停止时取消推理和文本请求，未完成的分段丢弃。
- 原始音频只在内存和匿名 `memfd` 中传给本地二进制，不写临时 WAV 文件。文字通过进程管道发送，不出现在命令行参数中。
- 本应用不保存音频、原文或译文；会话历史仅含元数据，文本 API Key 单独保存在系统密钥库。Codex 的 `--ephemeral` 不写会话 rollout，云端处理仍受对应服务的数据规则约束。

## 验证

2026-09-14 使用本地已有官方英文样本实测，Vulkan 识别 4 秒音频约 0.245 秒、7.18 秒音频约 0.274 秒，首次 2 秒音频约 0.506 秒，均包含当前逐段启动进程和加载模型的开销。对应 CPU 为 0.186 / 0.353 / 0.579 秒（2 / 4 / 7.18 秒音频）。小样本显示主要等待来自分段及翻译，不能将界面总延迟全部归因于 ASR 计算；未为优化常驻 ASR 而更换已验证的识别运行时。可运行 `scripts/benchmark_asr.py 音频路径` 复测，不采集实时音频或调用付费翻译。

自动验证覆盖界面状态、模型与思考等级恢复、提示词传递、译文缓存、常驻服务的独立临时会话与取消清理、GPU 默认值、密钥隔离、字幕配对、静音分句、片段上限、两个兼容接口及重定向保护。自动 API 验证只使用回环测试服务器，不调用付费模型；上述独立基准脚本会调用 Codex。

```bash
python3 scripts/test.py
```

另外使用官方英文示例，通过独立的测试虚拟音频通道，验证了 **真实 PipeWire → Vulkan GPU → Luna → 字幕 → 正常停止**。该次 ASR 0.34 秒，分段结束至译文 8.75 秒。测试通道已清理；没有修改浏览器音频路由。
